# Bug 修复工作流程指南

## 概述

本文档定义了 EasyFile 项目中处理 Bug 的标准化流程，通过错误库和修复模板提高问题解决效率。

---

## 核心文档体系

### 1. ERROR_DATABASE.md - 错误知识库
**作用：** 记录所有已知错误及解决方案  
**使用时机：** 遇到新错误时首先查询  
**维护频率：** 每次解决新问题后更新

### 2. BUG_FIX_TEMPLATE.md - 修复模板
**作用：** 系统性排查和记录 Bug 修复过程  
**使用时机：** 错误库无匹配结果时  
**维护频率：** 随流程优化更新

### 3. TROUBLESHOOTING_*.md - 专题排查指南
**作用：** 深度解析特定类型错误  
**使用时机：** 遇到复杂问题需要深入理解时  
**维护频率：** 发现新模式后添加

## 完整工作流程

### 阶段 1：错误发生 🚨

**立即行动：**
1. ✅ 截图/复制完整错误信息
2. ✅ 记录复现步骤
3. ✅ 标记优先级（P0-紧急 / P1-高 / P2-中 / P3-低）

**不要：**
- ❌ 直接修改代码猜测解决
- ❌ 忽略错误堆栈信息
- ❌ 跳过复现步骤确认

---

### 阶段 2：知识库查询 🔍

**操作步骤：**

```bash
# 1. 打开错误库
打开 docs/ERROR_DATABASE.md

# 2. 提取关键词
从错误信息中提取 3-5 个关键词
例如：deactivated widget, ancestor, unsafe

# 3. 搜索匹配
使用编辑器搜索功能 (Ctrl+F / Cmd+F)
搜索关键词：deactivated, setState, RenderBox 等

# 4. 查看索引
浏览错误索引，找到最接近的类别
```

**查询结果分支：**

#### 分支 A：找到精确匹配 ✅

```
找到匹配错误条目
    ↓
阅读"触发场景"确认一致性
    ↓
选择"解决方案"（通常有 A/B/C 多个方案）
    ↓
应用方案到代码
    ↓
跳转到【阶段 5：验证修复】
```

**示例：**
```
错误: "Looking up a deactivated widget's ancestor is unsafe"
匹配: ERROR_DATABASE.md#e001
方案: 延迟 notifyListeners() 到下一帧
```

#### 分支 B：找到相似错误 ⚠️

```
找到相似但不完全匹配
    ↓
参考相似错误的"根本原因"和"解决方案"
    ↓
思考是否可以类比应用
    ↓
如果可以 → 尝试应用 → 跳转到【阶段 5】
如果不行 → 继续【阶段 3：系统性排查】
```

#### 分支 C：未找到匹配 ❌

```
错误库无相关记录
    ↓
继续【阶段 3：系统性排查】
```

### 阶段 3：系统性排查 🔬

**使用模板：** `BUG_FIX_TEMPLATE.md`

**步骤 1：创建排查文档**

```bash
# 复制模板创建新文档（可选，用于复杂问题）
cp docs/BUG_FIX_TEMPLATE.md docs/bugfix/TEMP-XXX-[简要描述].md

# 或直接在模板上填写（推荐简单问题）
```

**步骤 2：填写信息收集部分**

```
✅ 1.1 基本信息：日期、发现者、优先级
✅ 1.2 错误描述：简要 + 详细描述
✅ 1.3 完整错误堆栈：复制粘贴全部内容
✅ 1.4 复现步骤：1-2-3 列举
✅ 1.5 环境信息：Flutter 版本、设备等
✅ 1.6 相关代码文件：列出涉及文件
```

**步骤 3：问题分析**

```
✅ 3.1 问题分类：勾选最接近的类别
    - Widget 生命周期
    - 状态管理
    - 异步操作
    - UI 渲染
    - 性能
    - 平台特定

✅ 3.2 5 Why 分析：
    Why 1: [表面原因]
    Why 2: [深入一层]
    Why 3: [再深入]
    Why 4: [接近本质]
    Why 5: [根本原因] ⭐

✅ 3.3 时序分析（如果涉及异步/生命周期）：
    绘制事件时间线，标记错误发生点
```

**步骤 4：调试策略**

```dart
// 添加结构化日志
print('[DEBUG-BUGFIX-TEMP-XXX] 方法入口: methodName');
print('[DEBUG-BUGFIX-TEMP-XXX] 状态前: $_state');
// ... 操作 ...
print('[DEBUG-BUGFIX-TEMP-XXX] 状态后: $_state');
print('[DEBUG-BUGFIX-TEMP-XXX] mounted: $mounted, time: ${DateTime.now()}');
```

**记录：**
- 完整日志输出（带时间戳）
- 断点调试关键变量值
- 调用栈分析

### 阶段 4：制定修复方案 🛠️

**步骤 1：头脑风暴**

列出 2-3 个候选方案：

```
方案 A: [方案名]
  优点: [优势]
  缺点: [劣势]
  风险: 低/中/高

方案 B: [方案名]
  优点: [优势]
  缺点: [劣势]
  风险: 低/中/高

方案 C: [方案名]
  优点: [优势]
  缺点: [劣势]
  风险: 低/中/高
```

**步骤 2：方案选择**

考虑因素：
- ✅ 根本性解决（不是临时绕过）
- ✅ 风险可控
- ✅ 不影响其他功能
- ✅ 代码可读性
- ✅ 可维护性

**步骤 3：实施修复**

```dart
// 修改前
void problematicMethod() {
  updateData();
  notifyListeners(); // 问题点
}

// 修改后（添加注释说明）
void problematicMethod() {
  updateData();
  // [BUGFIX-EXXX] 延迟通知以避免 widget 树重建冲突
  // 参考: docs/ERROR_DATABASE.md#eXXX
  WidgetsBinding.instance.addPostFrameCallback((_) {
    notifyListeners();
  });
}
```

### 阶段 6：更新知识库 📚

**任务清单：**

#### 6.1 如果是新错误类型

```bash
# 1. 分配错误编号
根据类别分配：E0XX, E1XX, E2XX 等

# 2. 编写错误条目
打开 docs/ERROR_DATABASE.md
添加完整错误条目（参考模板）

# 3. 更新索引
在文档开头的索引部分添加链接
```

**错误条目必填项：**
```markdown
- 错误级别
- 错误信息（完整）
- 触发场景（至少 2 个）
- 根本原因（清晰解释）
- 解决方案（至少 1 个，最好 2-3 个）
- 预防措施
- 历史案例（本次案例）
```

#### 6.2 如果是已知错误

```markdown
# 在对应错误条目的"历史案例"部分添加

#### 历史案例
- **2025-12-01**: 批量添加收藏功能触发
  - 场景：PopupMenu 选择"添加收藏"
  - 原因：notifyListeners() 在 PopupMenu 关闭前调用
  - 解决：延迟 notifyListeners() 到下一帧
  - 提交：[commit-hash]

- **[今天日期]**: [本次案例简述]
  - 场景：[具体场景]
  - 原因：[触发原因]
  - 解决：[解决方法]
  - 提交：[commit-hash]
```

#### 6.3 更新相关文档

```bash
# 如果发现新模式，考虑创建专题指南
docs/TROUBLESHOOTING_[主题].md

# 更新 CHANGELOG
docs/CHANGELOG.md
```

### 阶段 7：代码提交 📝

**清理工作：**

```bash
# 1. 移除调试日志
移除所有 [DEBUG-BUGFIX-TEMP-XXX] 日志

# 2. 保留说明注释
保留 [BUGFIX-EXXX] 注释，说明修复原因

# 3. 代码格式化
dart format .

# 4. 静态分析
flutter analyze
```

**Commit Message 标准：**

```
fix(scope): [简要描述] (EXXX)

问题：
- 错误信息：[简要错误]
- 触发场景：[场景描述]
- 影响范围：[影响模块]

根本原因：
[1-2 句话说明根本原因]

解决方案：
- [方案描述]
- 修改文件：
  - file_1.dart: [修改说明]
  - file_2.dart: [修改说明]

验证：
- 复现步骤测试：通过
- 回归测试：通过
- 性能影响：无

参考文档：
- ERROR_DATABASE.md#eXXX
- [相关文档链接]
```

**示例：**
```
fix(favorites): 修复选择模式批量添加收藏崩溃 (E001)

问题：
- 错误信息：Looking up a deactivated widget's ancestor is unsafe
- 触发场景：选择模式下从 PopupMenu 添加收藏
- 影响范围：收藏功能不可用

根本原因：
notifyListeners() 在 PopupMenu 关闭前触发，导致 widget 树重建冲突

解决方案：
- 延迟 notifyListeners() 到下一帧执行
- 修改文件：
  - lib/viewmodels/file_viewmodel.dart: batchAddFavoriteFiles 方法

验证：
- 复现步骤测试：通过
- 回归测试：其他批量操作正常
- 性能影响：无

参考文档：
- ERROR_DATABASE.md#e001
- TROUBLESHOOTING_DEACTIVATED_WIDGET.md
```

## 时间投入指南

### 快速通道（错误库匹配）⚡
- **时间：** 5-15 分钟
- **流程：** 查询 → 应用 → 验证 → 更新
- **适用：** 已知错误类型

### 标准通道（新问题排查）🔧
- **时间：** 1-4 小时
- **流程：** 完整模板流程
- **适用：** 未知错误，需要调试

### 复杂问题（深度排查）🔬
- **时间：** 4+ 小时
- **流程：** 完整模板 + 专题文档 + 团队协作
- **适用：** 疑难杂症，影响重大

## 快速参考卡片 🃏

### 遇到错误时 3 步走

```
1️⃣ 搜索错误库
   docs/ERROR_DATABASE.md
   
2️⃣ 找到匹配？
   有 → 应用方案
   无 → 使用模板
   
3️⃣ 解决后更新
   添加/更新错误库条目
```

### 常见错误快速查询

| 关键词 | 错误 ID | 快速方案 |
|--------|---------|----------|
| deactivated widget | E001 | 延迟 notifyListeners |
| setState after dispose | E002 | 检查 mounted |
| setState during build | E101 | 移到 PostFrameCallback |
| RenderBox layout | E301 | 使用 Expanded/SizedBox |

### 紧急情况处理

```
P0 紧急（生产环境崩溃）
  ↓
1. 立即回滚/热修复
2. 分析根本原因
3. 完整流程修复
4. 加强测试

P1 高优先级（功能受阻）
  ↓
1. 使用快速通道修复
2. 当天内部署
3. 更新文档

P2/P3 中低优先级
  ↓
按标准流程处理
```

**时间线：**

## 常见问题 FAQ

**Q1: 每个 Bug 都要填写完整模板吗？**
A: 不需要。简单问题（5 分钟内解决）只需口头记录，复杂问题才需要完整模板。

**Q2: 错误库和模板的区别是什么？**
A: 错误库是"字典"（查询已知答案），模板是"地图"（探索未知问题）。

**Q3: 如何判断是否需要添加到错误库？**
A: 如果：1) 调试时间 > 30 分钟，或 2) 可能再次出现，就应该添加。

**Q4: 团队新人如何使用这套系统？**
A: 先阅读本文档，然后在实际问题中练习使用，老员工 Code Review 时指导。

**Q5: 如果错误库中的方案不适用怎么办？**
A: 参考"相似错误"的思路，使用模板系统性排查，解决后更新错误库。
