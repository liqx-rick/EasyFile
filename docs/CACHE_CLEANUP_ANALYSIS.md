## 1. 现状分析

### 1.1 应用缓存使用情况

> 注意：本文档关注缓存清理场景与策略；若需要关于“应用推荐模块”运行时行为（首页推荐卡片、推荐页、RecommendationService 的实现等）的权威事实说明，请参阅 [docs/RECOMMENDATION_MODULE_REFERENCE.md](docs/RECOMMENDATION_MODULE_REFERENCE.md)。


通过代码审查，发现应用当前使用以下几种缓存机制：

#### 1.1.1 视频/音频缩略图缓存
**位置**：`lib/utils/thumbnail_cache_manager.dart`

```dart
/// 缩略图缓存管理器
/// 负责视频缩略图和音频封面的缓存管理
/// 使用文件系统缓存，通过MD5生成唯一键
class ThumbnailCacheManager {
  // 缓存位置：{ApplicationDocuments}/media_thumbnails/
  // 文件命名：MD5(文件路径).jpg
}
```

**特点**：
- 存储位置：`getApplicationDocumentsDirectory()/media_thumbnails/`
- 缓存内容：视频缩略图、音频封面
- 命名方式：使用文件路径的 MD5 值
- 已提供功能：
  - ✅ `getCacheSize()` - 获取缓存大小
  - ✅ `getCacheCount()` - 获取缓存文件数量
  - ✅ `clearCache()` - 清空所有缓存
  - ✅ `deleteCached()` - 删除单个缓存
  - ✅ `formatCacheSize()` - 格式化显示大小

#### 1.1.2 Flutter 图片内存缓存
**位置**：`lib/main.dart`

```dart
// 配置图片缓存，限制内存使用
PaintingBinding.instance.imageCache.maximumSize = 100; // 最多缓存100张图片
PaintingBinding.instance.imageCache.maximumSizeBytes = 50 << 20; // 50MB
```

**特点**：
- 类型：内存缓存（非持久化）
- 容量限制：100张图片或50MB
- 自动管理：Flutter 框架自动清理
- 无需手动清理：应用关闭后自动释放

#### 1.1.3 分类文件扫描缓存
**位置**：`lib/core/services/category_file_cache_service.dart`

```dart
/// 分类文件缓存服务
/// 负责缓存首次扫描时收集的各分类文件数量和最近扫描时间
class CategoryFileCacheService {
  // 缓存内容：分类文件统计数据
  // 存储方式：SharedPreferences
  // 有效期：7天

```

**特点**：
- 存储方式：SharedPreferences（轻量级键值对）
- 缓存内容：JSON格式的分类统计数据
- 缓存大小：< 1KB（仅统计数字）
- 有效期：7天自动失效
- 已提供功能：
  - ✅ `clearCache()` - 清除缓存

#### 1.1.4 视频时长缓存
**位置**：`lib/data/services/video_thumbnail_load_queue.dart`

```dart
// 1. 优先从SharedPreferences缓存加载
final prefs = await SharedPreferences.getInstance();
final cacheKey = 'video_duration_$videoPath';
final cachedDuration = prefs.getString(cacheKey);
```

**特点**：
- 存储方式：SharedPreferences
- 缓存内容：视频时长字符串
- 缓存大小：每条约100字节
- 估算：1000个视频 ≈ 100KB

#### 1.1.5 其他 SharedPreferences 数据
审查发现还有以下持久化数据：
- 收藏夹列表
- 最近访问文件
- 快速访问文件夹
- 主题设置
- 搜索历史
- 文件显示设置
- 视图模式设置
- 排序设置

**注意**：这些是应用核心数据，不应归类为"缓存"。

### 1.2 存储空间估算

| 缓存类型 | 存储位置 | 预估大小 | 增长速度 |
|---------|---------|---------|---------|
| 视频/音频缩略图 | 文件系统 | 1-5MB/100个视频 | 快 |
| 图片内存缓存 | 内存 | 最多50MB | 自动清理 |
| 分类统计缓存 | SharedPreferences | < 1KB | 几乎不增长 |
| 视频时长缓存 | SharedPreferences | < 500KB | 中等 |
| 日志文件 | 文件系统 | 可能较大 | 持续增长 |

**关键发现**：
1. **缩略图缓存**是主要占用空间的部分
2. 缓存管理器已经实现了清理功能
3. 日志文件可能无限增长（当前无清理机制）

## 2. 需求分析

### 2.1 用户痛点识别

#### 2.1.1 潜在问题
1. **存储空间占用**
   - 大量视频缩略图累积
   - 长期使用后可能占用数十MB
   - 低存储设备用户可能关注

2. **缓存失效**
   - 源文件移动/删除后，缓存成为"垃圾数据"
   - 用户无法主动清理这些无效缓存

3. **隐私考虑**
   - 缩略图可能暴露用户浏览记录
   - 敏感视频的缩略图残留

4. **日志文件**
   - 日志持续追加，无自动清理
   - 可能占用大量空间

#### 2.1.2 用户需求强度评估

| 用户群体 | 需求强度 | 原因 |
|---------|---------|------|
| 普通用户 | ⭐⭐ (低) | 缓存大小可控，自动管理有效 |
| 低存储设备用户 | ⭐⭐⭐⭐ (高) | 每MB空间都很宝贵 |
| 隐私敏感用户 | ⭐⭐⭐ (中) | 关注浏览痕迹清理 |
| 重度使用者 | ⭐⭐⭐ (中) | 大量视频导致缓存积累 |

### 2.2 竞品分析

主流文件管理器的缓存管理功能：

| 应用 | 缓存清理功能 | 实现方式 |
|-----|-------------|---------|
| Files by Google | ✅ 有 | 设置 → 清理缓存 |
| Solid Explorer | ✅ 有 | 设置 → 缓存与数据 |
| ES 文件浏览器 | ✅ 有 | 工具 → 清理 |
| 小米文件管理器 | ✅ 有 | 设置 → 存储管理 |

**结论**：缓存清理是文件管理器的**标配功能**。

### 2.3 功能必要性评分

综合评估（满分10分）：

| 评估维度 | 得分 | 说明 |
|---------|------|------|
| 用户需求 | 7/10 | 部分用户有明确需求 |
| 竞品对比 | 9/10 | 竞品均有此功能 |
| 实现成本 | 9/10 | 基础设施已完备 |
| 用户体验 | 8/10 | 提供控制感和安全感 |
| 维护成本 | 8/10 | 代码简单，易维护 |

**总分**：41/50 = 8.2/10

**结论**：**有必要实现**

## 4. 方案评估与建议

### 4.1 利弊分析

#### 优点 ✅
1. **满足用户需求**
   - 解决存储空间焦虑
   - 提供隐私保护手段
   - 符合用户使用习惯

2. **实现成本低**
   - 基础设施已完备（90%代码已存在）
   - 主要工作是UI和协调
   - 维护成本低

3. **提升应用专业度**
   - 竞品标配功能
   - 完善设置页面
   - 体现对用户的关怀

4. **可扩展性好**
   - 可逐步添加更多清理项
   - 可集成存储空间分析
   - 为未来功能打基础

#### 缺点 ❌
1. **可能被滥用**
   - 用户频繁清理影响体验（缩略图需重新生成）
   - 需要教育用户缓存的作用

2. **增加维护负担**
   - 需要确保不误删用户数据
   - 需要处理各种异常情况

3. **收益有限**
   - 对普通用户价值不大
   - 缓存本身有自动管理机制

### 4.2 最终建议

#### ✅ 建议实现（方案A - 简单版）

**理由**：
1. **用户期望**：竞品均有此功能，用户会寻找此选项
2. **实现简单**：基础代码已完备，仅需UI集成
3. **完善产品**：填补设置页面的功能空白
4. **未来扩展**：为高级功能（存储分析）铺路

#### 实施建议

**优先级**：🟡 中等（非紧急，但应尽快实施）

**第一期实现**（2-3小时）：

- ✅ 显示缓存大小

- ✅ 清理后提示反馈

**第二期扩展**（可选）：
- 清理搜索历史

**UI位置**：


### 4.3 关键注意事项

⚠️ **安全边界**：
- ✅ 可以清理：缩略图、日志、临时数据、分类缓存
- ❌ 不可清理：收藏夹、最近文件、快速访问、主题设置、文件显示设置

⚠️ **用户体验**：
- 显示清理前后的空间对比
- 提供"查看详情"选项
- 清理后不刷新当前文件列表（避免干扰）
- 添加"清理缩略图将导致下次加载变慢"的提示

⚠️ **性能考虑**：
- 异步执行清理操作
- 显示清理进度（如果耗时较长）
- 避免在主线程执行IO操作
