# 负一屏智能助手页（AssistantPage）功能设计方案

基于三屏智能架构方案 - 第一阶段

---

## 一、负一屏产品目标

### 1.1 明确定位
智能助手页是应用的"主动服务中心"，核心价值是**变被动为主动**：不等用户手动查找问题，而是自动发现设备上需要处理的文件优化机会，并以清晰的任务卡片形式推送给用户，降低文件管理门槛，提升使用效率。

### 1.2 与主页（0屏）的区别
- **主页**：被动浏览工具，用户需要知道"我要找什么文件"，核心是快速访问和分类浏览
- **负一屏**：主动发现工具，系统告诉用户"你的设备有什么问题需要处理"，核心是智能推荐和优化建议

### 1.3 与工具页（+1屏）的区别
- **工具页**：功能目录，展示所有可用的专业工具，用户需要主动选择使用哪个工具
- **负一屏**：任务中心，系统自动分析后推送最需要处理的任务，用户只需决定是否执行

简而言之：主页是"地图"，工具页是"工具箱"，负一屏是"贴心管家"。

---

## 二、页面整体结构

### 2.1 模块分区说明
负一屏采用纵向滚动单页布局，从上到下依次为：

1. **顶部导航栏 **：显示"智能助手"标题 + 刷新按钮
2. **智能任务卡模块**：动态生成的待办事项（2-5个）
3. **快速操作模块**：6个固定工具入口（2行3列网格）
4. **简要统计模块**：存储空间与文件数量概览
5. **最近活动模块**：用户近期操作记录摘要（3-5条）

### 2.2 模块排列顺序
按照用户注意力优先级排序：
- **任务卡优先**：因为这是页面核心价值，需要用户立即关注
- **快速操作次之**：提供快速跳转通道，满足用户主动查找需求
- **统计和活动垫底**：属于信息展示，无需立即操作

### 2.3 每个模块存在的目的

**智能任务卡**：
- **作用**：主动推送优化建议，创造使用场景
- **价值**：让用户"有事可做"，而非打开页面后迷茫

**快速操作**：
- **作用**：为高频功能提供快捷入口，减少跳转层级
- **价值**：满足"我知道要做什么，直接去做"的主动需求

**简要统计**：
- **作用**：突出存储空间紧迫性和用户清理成果，避免与存储管理页重复
- **价值**：建立空间压力感知，提供正反馈

**最近活动**：
- **作用**：记录用户的清理成果，提供正反馈
- **价值**：增强成就感，鼓励持续使用

## 三、核心模块详细功能说明

### 3.1 智能任务卡模块

#### 任务来源
系统自动扫描设备文件，根据以下规则生成任务：

1. **重复文件任务**：发现多个完全相同的文件（相同内容）
2. **大文件任务**：发现超过100MB的单个文件
3. **系统回收站清理任务**：Android系统回收站中有长期未清理的文件（注：不同厂商的系统回收站实现不同，部分设备可能没有此功能）
4. **安装包清理任务**：发现APK安装包文件
5. **应用缓存提醒任务**：发现可清理的应用缓存（提醒类，跳转应用管理页由用户操作）

#### 任务生成逻辑（功能层）
- **触发时机**：应用启动时、用户下拉刷新时、后台定时扫描后
- **生成条件**：
  - 重复文件：至少2组重复，可节省空间 > 50MB
  - 大文件：至少1个文件 > 100MB
  - 系统回收站：文件数 > 10个 或 总大小 > 100MB（需设备支持系统回收站）
  - 安装包：APK数量 > 3个 或 总大小 > 50MB
  - 应用缓存：可清理总大小 > 200MB

#### 显示数量规则
- **最少显示**：1个任务（若无任务显示"设备状态良好"占位卡）
- **最多显示**：5个任务
- **空状态**：若扫描未完成，显示"正在扫描设备..."占位卡

#### 优先级规则
任务按影响大小和紧急程度综合排序，优先显示：

1. **可节省空间大小**：1GB > 500MB > 100MB
2. **紧急程度**（同等空间大小时）：
   - 系统回收站（长期未清理，隐藏占用，用户往往忽略）
   - 重复文件（100%可安全删除）
   - 安装包（安装后通常可删除）
   - 大文件（需用户判断）
   - 应用缓存（提醒类，需跳转系统设置）

示例：
- 可节省2GB的重复文件 > 可节省300MB的系统回收站文件
- 可节省200MB的系统回收站文件 > 可节省200MB的重复文件（同等大小时回收站优先）
- 100MB安装包 > 100MB应用缓存（安装包可直接删除，缓存需跳转）

#### 用户交互行为

**主操作按钮（"立即清理" / "查看详情"）**：
- 点击后跳转到对应功能页面（如重复文件页、垃圾清理页）
- 跳转时自动触发该功能页的扫描或直接展示结果（利用缓存）

**次要按钮（"忽略" / "稍后"）**：
- 点击后该任务卡从列表中移除
- 任务不会永久消失，下次刷新页面时若条件仍满足则重新出现

#### 空状态策略
- **扫描中**：显示骨架屏或加载动画 + 文字"正在扫描，请稍候..."
- **无任务**：显示友好提示卡"设备状态良好，暂无优化建议"
- **扫描失败**：显示错误提示"扫描失败，请稍后重试" + 手动刷新按钮

---

### 3.2 快速操作模块

#### 固定入口数量
**6个固定入口**，采用3列2行网格布局（或2列3行，视设计而定）

#### 入口内容
1. **大文件**：跳转大文件列表页
2. **重复**：跳转重复文件扫描页
3. **回收站**：跳转系统回收站页面（若设备支持）
4. **安装包**：跳转APK安装包管理页
5. **应用缓存**：跳转应用管理页（显示应用缓存）
6. **新文件**：跳转新增文件列表页（最近7天）

#### 存在意义
- 解决智能任务卡的局限性（任务卡只显示有问题的项）
- 满足用户主动探索需求（"我想看看有没有大文件"）
- 提供固定入口，避免用户在主页和工具页间迷失

#### 是否允许自定义
**第一阶段不支持自定义**，原因：
- 这6个功能覆盖最高频场景，已足够
- 避免增加配置复杂度，降低开发成本
- 第二阶段可根据用户反馈考虑开放自定义（如拖拽排序、更换入口）

---

### 3.3 简要统计模块

#### 展示哪些指标

**核心原则**：避免与"存储管理页"重复，聚焦于"变化"和"行动提示"

1. **存储空间健康度**（条件显示）：
   - 仅在空间紧张时显示警告
   - 可用空间 < 20%：显示橙色提示"存储空间不足 XX GB"
   - 可用空间 < 10%：显示红色警告"存储空间告急 XX GB"
   - 可用空间 >= 20%：不显示或显示绿色"存储空间充足"

2. **本周活动统计**（二选一）：
   - **方案A**：本周新增文件 XXX 个，共 XX GB
   - **方案B**：本周已清理 XX GB 空间（更有成就感）

3. **智能推荐命中率**（可选）：
   - 本周发现 X 个优化机会，已处理 X 个

#### 指标更新逻辑

**数据同源要求**（避免重复计算）：
- **存储空间**：复用 `StorageStatService` 的缓存数据，与存储管理页保持一致
- **新增文件**：复用 `NewFilesService` 的统计结果
- **清理记录**：从 `AppTrashManager` 和操作日志聚合统计

**更新策略**：
- 页面加载时从缓存读取（立即显示）
- 后台异步刷新（更新最新数据）
- 与存储管理页共享同一份缓存，避免重复扫描

#### 是否可点击进入详情
- **可点击**：点击统计卡片跳转到存储管理页（详细的分类占比和存储趋势）
- **视觉提示**：卡片右侧显示箭头图标，暗示可点击
- **跳转逻辑**：直接复用存储管理页的数据，无需重新加载

---

### 3.4 最近活动模块

#### 显示内容类型
记录用户最近的文件管理操作：
- 清理操作（如"清理了234MB垃圾文件"）
- 整理操作（如"整理了12个重复文件"）
- 隐私操作（如"移入隐私空间3个文件"）
- 其他管理操作（如"删除了5个大文件"）

#### 展示条数
**最多显示5条**，按时间倒序排列（最新的在最上面）

#### 目的
- **正反馈**：让用户看到自己的清理成果，增强成就感
- **透明化**：展示系统记录的操作历史，增加信任感
- **引导复用**：提醒用户"上次清理有效"，鼓励再次使用

## 四、数据刷新与触发机制（功能级说明）

### 4.1 首次进入如何处理
用户首次进入负一屏时：
1. **优先加载缓存**：立即显示上次扫描结果（若有）
2. **后台触发扫描**：启动后台扫描任务，更新缓存
3. **增量更新UI**：扫描完成后，逐步更新任务卡内容（如数字变化、新任务出现）

### 4.2 后台刷新策略
- **触发条件**：应用从后台切回前台超过30分钟、设备文件变化超过50个
- **刷新方式**：增量扫描（只扫描新增/修改的文件），而非全量重新扫描
- **用户感知**：静默刷新，不打断用户操作，刷新完成后自动更新UI

### 4.3 用户主动刷新逻辑
- **触发方式**：点击顶部刷新按钮，或下拉刷新手势
- **刷新反馈**：显示加载动画（转圈或进度条）+ 文字提示"正在刷新..."
- **刷新完成**：任务卡数字更新、新任务出现、无效任务移除

## 五、边界与风险控制

### 5.1 无数据设备如何处理
**场景**：新手机、刚恢复出厂设置、文件很少的设备

**处理方式**：
- 智能任务卡显示"设备状态良好，暂无优化建议"占位卡，配详细说明：
  ```
  ✅ 设备状态良好
  - 无重复文件
  - 系统回收站已清空
  - 无大文件占用
  ```
- 快速操作模块仍正常显示（用户可主动进入查看）
- 简要统计显示"存储空间充足"或"本周暂无新增文件"
- 最近活动显示"暂无操作记录"

**避免问题**：页面不能完全空白，必须有友好提示说明为什么没有任务

### 5.2 权限拒绝如何处理
**场景**：用户拒绝存储权限、文件访问权限

**处理方式**：
- 整页显示权限请求引导卡片："需要存储权限以扫描文件" + [授权]按钮
- 点击按钮后跳转到系统权限设置页
- 权限授予后自动刷新页面并开始扫描

**避免问题**：不能显示错误提示或崩溃，必须提供明确的解决路径

### 5.3 扫描未完成如何表现
**场景**：用户刚进入页面，后台扫描还在进行中

**处理方式**：
- 任务卡区域显示骨架屏（灰色占位块）+ 文字"正在扫描设备..."
- 快速操作、简要统计、最近活动正常显示（这些数据可实时获取）
- 扫描完成后，骨架屏淡出，真实任务卡淡入

**避免问题**：不能显示空白或"暂无数据"，必须明确告知扫描进度

### 5.4 性能风险如何避免
**风险**：扫描大量文件导致卡顿、内存占用过高

**控制措施**：
- **任务卡最多5个**：避免列表过长
- **统计数据缓存**：避免每次都实时计算
- **分批加载**：先显示高优先级任务，低优先级任务延迟加载
- **超时保护**：扫描超过10秒仍未完成，先显示部分结果并标注"扫描中..."

## 六、第一阶段验收标准（可量化）

以下标准必须全部满足才能提交审核：

### 6.1 功能完整性
- [ ] 至少生成1个智能任务卡（在有优化空间的设备上）
- [ ] 6个快速操作入口全部可点击并跳转到正确页面
- [ ] 简要统计正确显示（空间紧张时显示警告，或显示本周活动数据）
- [ ] 最近活动显示至少1条记录（若有操作历史）

### 6.2 交互有效性
- [ ] 任务卡的"立即清理"按钮可跳转到对应功能页
- [ ] 任务卡的"忽略"按钮可移除当前任务
- [ ] 统计卡片可点击跳转到存储管理页
- [ ] 顶部刷新按钮可触发重新扫描

### 6.3 空状态友好性
- [ ] 无任务时显示"设备状态良好"而非空白
- [ ] 扫描中显示"正在扫描..."而非"暂无数据"
- [ ] 权限拒绝时显示授权引导而非错误提示

### 6.4 性能指标
- [ ] 页面首次加载时间 < 1秒（优先显示缓存）
- [ ] 后台扫描不阻塞UI交互（不卡顿）
- [ ] 内存占用 < 100MB（在负一屏停留时）

### 6.5 数据准确性
- [ ] 重复文件任务显示的可节省空间与实际扫描结果一致
- [ ] 大文件任务显示的文件数与实际文件数一致
- [ ] 简要统计数据与存储管理页数据同源，无差异
- [ ] 存储空间健康度判断准确（百分比计算正确）

### 6.6 视觉一致性
- [ ] 任务卡、快速操作卡、统计卡设计风格统一
- [ ] 所有图标清晰且符合Material Design规范
- [ ] 文字大小、颜色、间距符合设计规范

---

## 验收方式

1. **新设备测试**：在全新或恢复出厂设置的设备上测试空状态表现
2. **数据设备测试**：在文件较多的设备上（如使用1年以上的手机）测试任务生成准确性
3. **权限测试**：拒绝存储权限后测试引导流程是否顺畅
4. **性能测试**：使用性能监控工具验证内存占用和加载速度

---

**总结**：负一屏的核心是"主动发现问题 + 快速解决问题"，第一阶段聚焦于基础功能的可用性和稳定性，确保用户打开页面后"有事可做、做了有效、体验流畅"。

## 附录：任务卡设计说明

### A1. 任务类型分类

**行动类任务**（可直接处理）：
- 重复文件：点击后跳转清理页面，可直接删除
- 系统回收站：点击后跳转系统回收站页面，可直接清空（需设备支持）
- 安装包：点击后跳转APK列表，可直接删除

**检查类任务**（需用户判断）：
- 大文件：点击后跳转列表，用户自行判断是否删除

**提醒类任务**（引导操作）：
- 应用缓存：点击后跳转应用管理页，需用户进入系统设置清理

### A2. 第一阶段不包含的任务（及原因）

**垃圾文件任务**：
- 原因：功能不完善，误判风险高
- 替代方案：已拆分为"安装包清理"（准确度高）
- 第二阶段计划：完善识别规则后重新引入

**截图整理任务**：
- 原因：需要新开发截图识别功能
- 替代方案：快速操作中保留"新文件"入口
- 第二阶段计划：配合智能相册一起实现

**本周新增文件任务**：
- 原因：缺少明确的"行动点"，只是信息展示
- 替代方案：已放入快速操作区和简要统计模块
- 第二阶段计划：增强为"新增文件分类提醒"

### A3. 第二阶段扩展方向

**智能整理类任务**：
1. 截图整理：配合智能相册实现
2. 表情包整理：识别小尺寸图片
3. 证件照整理：识别特定尺寸比例

**深度清理类任务**：
1. 僵尸文件夹：3个月未更新的目录
2. 重复文档版本：同名不同版本的文档
3. 空文件夹：递归检测空目录

**数据洞察类任务**：
1. 存储空间告急：可用空间 < 10%
2. 文件增长异常：本周新增 > 平均值的2倍
3. 特定应用占用过大：某应用文件 > 5GB

### A4. 系统回收站说明

**重要说明**：
- 系统回收站是Android 11+引入的系统级功能，用于暂存用户删除的文件
- 不同厂商的实现方式和规则不同（小米、华为、OPPO、vivo等各有自己的回收站机制）
- 系统回收站中的文件通常有保留期限（如30天），但部分厂商的回收站可能不会自动清理
- 数据来源：通过MediaStore API访问系统回收站的文件统计

**不同厂商实现差异**：
- **原生Android**：回收站文件自动保留30天后清除
- **小米MIUI**：回收站可能需要手动清理，没有严格的自动清理机制
- **华为HarmonyOS/EMUI**：回收站保留时间可自定义，部分版本需手动清理
- **OPPO ColorOS**：回收站文件保留30天，但从其他设备迁移的回收站文件可能不会自动清理
- **vivo OriginOS**：类似实现，需要关注设备迁移场景

**为什么推荐为高优先级任务**：
- 很多用户不知道系统回收站的存在，尤其是从旧设备迁移数据后
- 设备迁移时，旧设备回收站中的文件可能被一并迁移，但新设备的自动清理机制不会识别这些"历史"文件
- 长期未清理会隐藏占用大量存储空间（有些用户回收站占用超过10GB）
- 回收站文件通常是用户已决定删除的，再次确认删除的意愿强

**技术实现注意事项**：
- 需要检测设备是否支持系统回收站功能（Android版本 >= 11）
- 需要处理不同厂商的API差异
- 对于不支持系统回收站的设备，该任务卡不显示
- 清理操作应调用系统API，确保符合厂商的回收站机制

### A5. 简要统计模块设计说明

**为什么不重复显示总存储/可用空间**：
- **避免功能重复**：存储管理页已详细展示总容量、可用空间、分类占比等完整数据
- **聚焦差异化价值**：负一屏是"智能助手"，应聚焦于"主动提醒"和"变化趋势"，而非静态数据
- **降低信息噪音**：重复显示相同数据会降低页面的信息密度和用户关注度

**改进方案的核心逻辑**：

1. **条件显示，而非常驻显示**：
   - 空间充足（>20%）：不显示或显示简单的绿色提示
   - 空间紧张（10-20%）：显示橙色警告 + 剩余空间
   - 空间告急（<10%）：显示红色警告 + 剩余空间 + 建议清理量

2. **突出"变化"而非"状态"**：
   - **本周新增**：强调增长趋势，提醒用户关注文件积累
   - **本周清理**：强调清理成果，提供正反馈和成就感
   - 推荐优先显示"本周清理"（正向激励效果更好）

3. **数据同源保证**：
   ```
   存储空间数据流：
   disk_space_plus → StorageStatService（缓存） →
     ├─ 存储管理页（详细展示）
     └─ 智能助手页（条件提示）

   避免：
   disk_space_plus → 智能助手页直接读取（重复计算）
   ```

**推荐显示方案**（二选一）：

**方案A：聚焦清理成果**
```
📊 本周成果
- 已清理 2.3 GB 空间
- 整理了 156 个重复文件
[查看详情 →]
```

**方案B：聚焦文件增长**
```
📊 本周活动
- 新增 458 个文件（共 3.2 GB）
- 已清理 2.3 GB 空间
[查看详情 →]
```

**方案C：聚焦空间健康**
```
⚠️ 存储空间紧张（仅当可用<20%时显示）
- 剩余 12.5 GB（可用10%）
- 建议清理至少 5 GB
[立即清理 →]
```

**推荐组合**：
- 默认显示方案A（成就感强）
- 当可用空间 < 20% 时，替换为方案C（紧迫性强）
- 点击任意方案都跳转到存储管理页

**数据刷新策略**：
- 与智能任务卡共用同一次扫描结果
- 优先从 StorageStatService 缓存读取
- 避免独立触发存储空间扫描
